# 로봇 텔레메트리 및 명령 계약

이 문서는 펌웨어, 게이트웨이, 로그, 브라우저가 공유할 출발점이다. 특정 전송 형식이나 클라우드 공급자를 강제하지 않는 의미 계약이다. 현재 펌웨어와 브라우저는 아래의 40바이트 v2 패킷을 사용한다. 이전 14바이트 v1은 웹 UI의 하위 호환 읽기 전용이다. 프로토콜을 바꾸기 전에 생산자와 소비자를 대조하고 명시적으로 버전을 올린다.

## 현재 바이너리 텔레메트리 v2

정수는 네트워크 바이트 순서(상위 바이트 우선)를 사용한다.

| 오프셋 | 길이 | 형식 | 의미 |
|---:|---:|---|---|
| 0 | 1 | uint8 | 패킷 ID `T` |
| 1 | 1 | uint8 | 버전 `2` |
| 2 | 2 | uint16 | bit 0: MPU9250 초기화, bit 1: 최신 IMU 샘플 유효, bit 2: INA219 초기화, bit 3: 최신 전력 샘플 유효, bit 4: 보행 ARM 상태 |
| 4 | 2 | int16 | IMU X축 각도, 0.01도 단위 |
| 6 | 2 | int16 | IMU Y축 각도, 0.01도 단위 |
| 8 | 2 | int16 | IMU Z축 각도, 0.01도 단위 |
| 10 | 24 | uint16[12] | LF, RF, LH, RH 순서로 각 다리 알파·베타·감마 명령 각도, 0.01도 단위 |
| 34 | 2 | uint16 | 버스 전압(mV) |
| 36 | 2 | int16 | 전류(mA) |
| 38 | 2 | uint16 | 메인 루프 시간(µs) |

IMU X/Y/Z는 센서 라이브러리가 반환하는 축 각도다. 로봇 장착 방향을 보정하기 전에는 roll/pitch/yaw로 해석하지 않는다. IMU 및 INA219 표시 최신성은 각각 서비스 갱신 주기의 4배와 전력 갱신 주기의 4배로 판정한다. INA219 기준은 표시용이며 동작 차단 임계값이 아니다. 반면 IMU 최신·유효성은 ARM 허용과 기기 측 동작 중지에 사용된다. 현재 IMU 기준은 `SERVICE_FAST_LOOP_TIME * 4`(기본 설정 20 ms)이며 보드·센서에서 검증된 물리 안전 임계값은 아니다. 상태 bit 0-3은 센서 초기화 및 샘플 유효성을, bit 4는 소프트웨어 ARM 상태를 나타낸다. 어느 것도 물리적 축 보정이나 자세 안정화를 보증하지 않는다. 서보 각도는 명령값이며 실측 피드백이 아니다. v1은 패킷 ID·버전·최소 길이를 확인한 후 UI에서만 읽고 새 텔레메트리를 생성하지 않는다.

## 텔레메트리 의미

서버나 다른 전송 형식으로 확장할 때는 다음 의미를 보존한다.

- `schema_version`, 고유한 `device_id`, 단조 증가하는 `sequence`, UTC 샘플 시각, 로컬 적산에 사용할 단조 경과 시간.
- `connection_state`, 현재 `gait`/동작 상태, `armed` 상태, 구조화된 오류·상태 정보.
- 보정 전에 IMU X/Y/Z 축 각도(도), 센서 준비·유효 상태와 샘플 경과 시간. 축 규약과 보정 방법을 문서화한 뒤에만 roll, pitch, yaw로 해석한다.
- 안정적인 식별자를 가진 관절 12개의 각도(도)와 `commanded` 같은 명시적 출처·의미. 하드웨어에서 실제 피드백이 제공될 때만 측정값을 포함한다.
- INA219 버스 전압(V), 전류(A), 계산된 전력(W)과 각각의 유효성·센서 상태. 시간 정보가 있는 샘플을 바탕으로 에너지(Wh)를 적산할 수 있다.
- 배터리 용량·충전 상태는 산정 방법과 보정 상태를 가진 null 허용 추정치로만 제공한다. 전압·전류 샘플만으로 정확한 잔량인 것처럼 표시하지 않는다.

값을 사용할 수 없으면 명시적인 무효 상태를 사용한다. 센서 누락을 그럴듯한 0으로 직렬화하지 않는다. 필드명 또는 명확한 스키마 정의로 단위를 표시한다.

## 원격 명령 봉투

원격 보행 명령은 게이트웨이/브로커를 거치는 인증 및 암호화된 사용자·기기 세션으로 전달한다. 명령 계약은 다음 항목을 포함한다.

- 고유 요청 ID, 단조 증가 시퀀스 또는 이에 준하는 재생 공격 방지 값, 발행 시각, 짧은 만료 시간, 허용 목록 기반 동작·방향, 제한된 매개변수.
- 명시적인 활성화/비활성화 전이. 비활성화, 만료, 권한 없음, 오류 상태에서는 명령을 거부한다.
- 수락, 시작, 정지, 거부 상태를 구분하는 확인 응답.
- 동작 제한 빈도에 의존하지 않고 동작보다 우선하는 전용 `STOP` 명령.

인증·권한 자격 증명은 텔레메트리 레코드, 정적 브라우저 코드, 로그가 아니라 전송·세션 계층에서 관리한다. ESP32에서도 명령을 재검증한다. 게이트웨이 시간 초과, 오래된 heartbeat, 기기 연결 끊김, 잘못된 안전 센서, 재부팅으로 동작이 지속되거나 자동 재개되어서는 안 된다. 인터넷 원격 제어 계약은 아직 제공하지 않는다. 로컬 WebSocket 프로토타입에서는 단일 제어 클라이언트만 허용하고 새 연결은 비활성화로 시작한다. ARM 요청은 정확히 `[0x41, sequence:uint8]`이며, 펌웨어가 MPU9250 초기화 및 최신 유효 샘플을 확인한 뒤 `ARMED:<sequence>` 또는 `ARM_REJECTED:<sequence>`를 반환한다. UI는 해당 sequence의 성공 응답을 받기 전에는 이동 패킷을 보내지 않는다. 이동 벡터 6개는 각각 정규화 범위 `[-1, 1]`을 나타내는 uint16 값 `[0, 20000]`만 허용한다. 즉시 정지는 응답을 요구하지 않는 한 바이트 `[0x53]`으로 언제나 수락하며, 기존 `P_MOVE`의 정지 플래그 0도 유지한다. 텔레메트리 요청은 정확히 `[0x54, 0x01]` 두 바이트다. 텔레메트리 v2의 bit 4(`0x0010`)는 현재 ARM 상태다. 정상 수락된 이동 패킷만 기기 감시 시간을 갱신한다. 감시 시간은 `micros()` 경과시간으로 판정한다. 웹 코어 명령은 짧은 임계 구역으로 보호된 대기 벡터를 거쳐 보행 코어 루프 경계에서 적용한다. ARM 중 IMU 샘플이 무효 또는 오래되면 기기 감시가 정지한다. 정지 후 진행 중인 다리 스윙은 목표 지점까지 마칠 수 있지만 새 스윙은 시작하지 않는다. 연결·재연결, 패킷 오류, 타임아웃 시 비활성화하며 자동 재개하지 않는다. 브라우저도 연결 해제, 오래된/무효 IMU 텔레메트리, 페이지 숨김 시 정지를 전송한다. 이 단계는 자세 축 보정, 안정화 제어 또는 기울기 안전 임계값을 구현하지 않는다.

## 로컬 로깅 및 에너지 적산

- 현재 브라우저는 텔레메트리 샘플을 `localStorage`에 최대 1,000건 저장하고 CSV로 내보낸다. 이는 브라우저별 로컬 로그이지 서버의 중앙 내구성 로그가 아니다.
- 순간 전력은 `전압_V * 전류_A`로 계산한다. 에너지는 연속으로 받은 유효한 샘플 사이의 `performance.now()` 단조 경과시간에 사다리꼴 적산을 적용해 Wh로 표시한다. UTC 표시 시각은 벽시계에서 가져오며, 벽시계 변경의 영향을 받지 않도록 적산과 샘플 신선도 판정은 단조 시계를 사용한다. 2.5초보다 긴 공백은 적산하지 않는다. 전류 방향이 검증되지 않았으므로 부호 있는 적산값으로 취급한다.
- 원본 측정값을 계산된 에너지, 추정 용량, 대시보드 표시 값과 구분한다.
- 배터리 잔량 추정, 서버 보존 기간, 오프라인 업로드, 개인정보, 중앙 내보내기는 아직 구현하지 않았다. 추가 시 사용자 또는 호스팅 설계와 정하고 로그를 조용히 버리지 않는다.

## 호환성 검사

프로토콜을 바꾸기 전에 실제 생산자와 소비자를 대조하고 바이트 순서·스케일링·길이·버전 동작을 확인한 뒤 호환성 또는 마이그레이션 경로를 제시한다. 현재 패킷에 인증 메타데이터, 장치 식별자, 시퀀스, 서버 시각이 있다고 가정하지 않는다.

## 로컬 모의 게이트웨이 API

`software/gateway/`는 현재 로봇 계약을 바꾸지 않는 로컬 전용 모의 경계다. 조회는 Bearer 토큰과 `viewer` 또는 `operator` 역할을 요구한다. 명령은 `operator`만 허용한다. ARM/MOVE는 사용자별 증가 sequence와 Unix 밀리초 발행·만료 시각을 가진 JSON envelope를 사용하며 유효 기간은 최대 3초다. `requestId`는 UUID 형식이어야 한다. 봉투와 명령은 알 수 없는 키를 거부하며 JSON 본문은 4 KiB로 제한한다. STOP은 유효한 인증·명령 형식은 요구하지만 명령 만료 및 순번 검사보다 우선하여 모의 장치를 비활성화한다. 이동 벡터 여섯 값은 기존 펌웨어 정규화 범위와 동일하게 `[0, 20000]`이다. 이 구현은 메모리 상태와 MockDevice만 사용하므로 다중 인스턴스 재생 방지, 실제 ID 공급자, TLS, 장치 인증, 인터넷 연결 또는 ESP32 명령 전달을 구현하지 않는다.
