# 기능 명세: 관절 기구학 모형 (실제 형태와 닮은 4다리 모델)

사용자 요청(2026-11-11): 로봇개의 실제 형태와 비슷한 모형을 만들고, 서보 값을 반영해 각 관절이 **같은 각도**로 움직이게 한다. 바닥과의 관계(발이 떴는지, 얼마나 이동했는지)를 표현하려는 것이 아니다. 관절 각도가 주어졌을 때 **네 다리가 어떤 모양이 되는지**를 모델링 데이터처럼 보는 것이 목적이다.

## 범위

- 한다: 몸통 기준 좌표계에서 순기구학으로 12개 관절을 그린다. 몸통은 고정이고 다리만 움직인다. 관절별 각도 값을 함께 표시한다.
- 하지 않는다: 바닥 접촉·발 뜸 판정, 몸통 이동·미끄러짐, 중력·하중, IMU 기울기로 몸통을 기울이는 표현(기울기는 수평 상태 카드가 담당). 바닥 격자는 방향 참고용으로만 두고 접촉을 뜻하지 않는다.

## 관절 의미와 순기구학

논리 각도(상태 응답 `angles`)는 관절 각도다. ALPHA의 기어비 2는 펌웨어가 처리하므로 모형에서는 다시 곱하지 않는다.

- **ALPHA** (어깨 좌우 벌림): 90° = 다리 평면이 수직. 다리 평면이 앞뒤 축(Y)을 중심으로 `90° − ALPHA`만큼 기운다.
- **BETA** (윗다리 앞뒤): 윗다리는 다리 평면 안에서 수직 아래 방향으로부터 **뒤쪽으로 `BETA`만큼** 기운다. BETA가 커지면 윗다리가 뒤로 간다(사용자 확인). 원본 IK 식(`90° − BETA`)과 방향이 반대이므로 원본 식을 그대로 쓰지 않는다. 중립 45°에서는 두 식이 같은 자세다.
- **GAMMA** (무릎): 윗다리와 아랫다리 **사이 각**. 90° = 직각, 커지면 다리가 펴져 길어진다(2026-11-11 실물: GAMMA를 늘리면 그쪽 몸이 올라감).
- 검증점: 중립 90/45/90에서 L2≈L3이므로 발이 어깨 바로 아래에 온다(윗다리 +45°, 아랫다리 −45°). 구현 후 이 조건을 테스트로 고정한다.

다리 평면 안 좌표(u = 무릎이 나가는 쪽, d = 아래):

```
θ2 = BETA                       // 윗다리, 아래 방향 기준 뒤쪽(+u)으로
θ3 = θ2 − (180° − GAMMA)        // 아랫다리
무릎 = L2·(sin θ2, cos θ2)
발   = 무릎 + L3·(sin θ3, cos θ3)
```

그 뒤 `90° − ALPHA`만큼 좌우로 기울여 몸통 좌표로 옮긴다.

## 사용자가 확인한 관절 방향 (2026-11-11)

1. 무릎은 **네 다리 모두 뒤쪽**으로 꺾인다 → u(무릎이 나가는 쪽) = −Y, 네 다리 공통.
2. **BETA를 키우면 윗다리가 뒤로** 간다 → `θ2 = BETA`.
3. **ALPHA를 키우면 다리가 안으로 모인다** → 바깥쪽 기울기 = `90° − ALPHA` (좌우 다리 모두 자기 쪽 바깥 기준, 좌우 거울 대칭).
4. 좌우 어깨 간격 80 mm.

## 아직 확정되지 않은 것 (추측하지 말 것)

- 앞뒤 어깨 간격(현재 141 mm = ±70.5, 원본 값).
- 실제 조립 상태에서 논리 90°가 기하학적 90°와 얼마나 다른지. `STAND_GAMMA_TRIM_DEG`(LF +9, RF +1, LH −1, RH −9)가 필요한 것으로 보아 무릎마다 조립 오프셋이 있다. 화면에 "명령 각도 기준"임을 표시한다.

## 어떤 각도를 그릴 것인가

- 기본: **서보에 실제로 나가는 명령 각도** = `angles` + `level.gammaOffsetDeg`(GAMMA만) + 서 있는 자세 보정(GAMMA만).
- 서 있는 자세 보정은 지금 상태 응답에 없다. 모형에 반영하려면 `embedded`가 상태 응답(직렬 `STATUS`와 Wi-Fi JSON 모두)에 필드를 추가하고 게이트웨이가 전달해야 한다 → **계약 변경**이므로 오케스트레이터를 통해 합의한다(제안 이름 `standTrimDeg {LF,RF,LH,RH}`, 도 단위). 합의 전에는 `angles` + `gammaOffsetDeg`만 그리고 그 사실을 표시한다.
- "기본 각도만 / 보정 포함" 전환을 둔다. 값이 없으면 0으로 가정하지 말고 "알 수 없음"으로 표시한다.
- 화면에 "명령 각도 기준 모형이며 서보 위치 피드백이 없어 실제 자세와 다를 수 있음"을 적는다.

## 화면

- 외부 라이브러리 없이 Canvas 2D로 직접 투영해 그린다(`current-web-stack.md`의 제약).
- **형태**: 실제 로봇과 닮게 — 긴 상자형 몸통, 앞뒤 어깨 블록(서보), 윗다리·아랫다리 링크, 관절 원, 발끝 구. 선 하나짜리 막대 인형이 아니라 두께가 있는 링크로 그린다. 앞쪽을 구분할 수 있게 표시한다(앞 표시, 좌/우 다리 색 또는 라벨).
- **보기**: 3D 투시(끌어서 회전) + 고정 보기 3개(옆·앞·위) 전환. 옆 보기에서는 BETA/GAMMA가, 앞 보기에서는 ALPHA가 왜곡 없이 보여야 한다.
- **모델링 데이터 표**: 다리별 ALPHA/BETA/GAMMA(기본값과 보정 포함값), 그리고 몸통 기준 무릎·발 좌표(mm). 기존 관절 표를 대체하거나 확장한다.
- **중립 자세 겹쳐 보기**: 90/45/90 자세를 옅은 선으로 함께 그려 현재 자세와의 차이를 보이게 한다(켜고 끌 수 있게).
- 관절 각도가 펌웨어 한계(20~160°) 밖이면 그 관절을 강조한다.
- 상태가 오래됐거나 연결이 끊기면 마지막 모형을 실시간처럼 남기지 않는다(흐리게 + "알 수 없음").
- 갱신은 폴링 주기(약 4 Hz)를 따른다. 보간으로 부드럽게 보이게 할 수는 있지만, 보간된 값을 표의 숫자로 쓰지 않는다.

## 테스트 (`tests/page_harness.js` 확장)

순기구학은 DOM과 분리된 순수 함수로 만들어 하네스에서 직접 호출한다.

- 중립 90/45/90: 발이 어깨 거의 바로 아래(앞뒤 오차 = (L2−L3)·sin45° ≈ 1.3 mm), 깊이 = (L2+L3)·cos45°.
- BETA가 커지면 무릎이 뒤(−Y)로 이동한다. 네 다리 모두 무릎의 Y가 어깨보다 뒤에 있다(BETA>0, GAMMA<180).
- ALPHA가 90°보다 크면 발이 몸 안쪽으로, 작으면 바깥쪽으로 이동한다.
- GAMMA 180°: 다리가 일직선, 어깨~발 거리 = L2 + L3. GAMMA가 커지면 어깨~발 거리가 단조 증가.
- ALPHA ≠ 90°: 발이 좌우로만 이동하고 어깨~발 거리는 변하지 않는다.
- 네 다리에 같은 각도를 주면 좌우 다리는 YZ 평면에 대해 거울 대칭이다.
- 링크 길이 보존: 모든 자세에서 어깨~무릎 = L2, 무릎~발 = L3.
- `level.gammaOffsetDeg`가 반영 모드에서만 더해진다. 필드가 없을 때 `NaN`이 나오지 않는다.
- 12개 관절 모두 표와 모형에 나타난다.
