# 기능 명세: 수평 유지 ON/OFF 비교 그래프

사용자 요청(2026-11-11): 웹 페이지에서 수평 유지 모드를 켜고 끄면서, 두 모드에서 수평이 얼마나 다르게 유지되는지 그래프로 비교한다.

## 목표

같은 조건(서 있기 또는 같은 방향 보행)에서 수평 유지 **꺼짐** 구간과 **켜짐** 구간의 roll/pitch를 나란히 보여 주고, 차이를 숫자로 요약한다.

## 데이터

- 입력은 기존 폴링(`api/status`, 약 4 Hz)의 `imu.rollDeg`/`imu.pitchDeg`, `level.enabled`/`level.active`, `armed`, `walk`다. 새 펌웨어 필드 없이 구현할 수 있다.
- 표본마다 모드를 붙인다. **켜짐 = `level.active`가 true**(`enabled`만 true이고 비활성 상태면 보정이 동작하지 않으므로 켜짐으로 세지 않는다). 꺼짐 = `level.enabled`가 false.
- 표본마다 조건(`walk` 값, `armed`)도 함께 기록해 **같은 조건끼리만** 비교한다. 서 있을 때의 꺼짐과 걷는 중의 켜짐을 비교하지 않는다.
- 축 설정이 없으면(`rollMap`/`pitchMap`이 `NONE`) 비교를 기록하지 않고 이유를 표시한다. `imu.valid`가 false인 표본은 버린다(0으로 채우지 않는다).
- 폴링 간격이 1.2초 넘게 벌어지면 선을 끊는다. 모드가 바뀐 직후 전환 구간(기본 1초, 상수)은 통계에서 제외한다.
- 기록은 브라우저 메모리에만 둔다(새로고침하면 사라짐을 표시). 구간당 최대 길이를 둔다(예: 모드별 최근 60초).

## 화면

- 기존 "수평 상태" 카드의 켜기/끄기 버튼과 30초 실시간 그래프는 유지한다.
- 비교 영역(같은 카드 안 또는 바로 아래 카드):
  - **겹쳐 보기 그래프**: 가로축은 구간 시작부터의 경과 시간, 꺼짐 구간과 켜짐 구간의 선을 겹쳐 그린다. roll과 pitch는 위아래 두 그래프로 나눈다(한 그래프에 4개 선을 섞지 않는다). 모드 구분은 색 + 선 모양(실선/점선)으로 하고 범례를 둔다.
  - **요약 표**: 모드별 표본 수·구간 길이, 평균, 평균 절대값, RMS, 최대 절대값, 최대-최소 폭. 그리고 켜짐이 꺼짐보다 얼마나 줄었는지(절대값과 %)를 roll/pitch 각각 표시한다.
  - **기록 제어**: "비교 기록 지우기" 버튼, 현재 어떤 모드·조건의 구간을 기록 중인지 표시. CSV 내려받기(Blob, 외부 통신 없음)를 넣는다.
- 한쪽 모드의 표본이 부족하면(기본 20개 미만) 차이를 계산하지 않고 "꺼짐/켜짐 구간이 더 필요합니다"로 안내한다.
- 차트 작업 전 `dataviz` 스킬을 읽는다. 기존 `--series-1/2` 색 변수와 밝은/어두운 테마를 따른다.

## 표현 한계 (화면에 적는다)

- 4 Hz 폴링이라 빠른 흔들림은 잡히지 않는다. 0.25초보다 짧은 변화는 그래프에 나타나지 않을 수 있다.
- 두 구간은 서로 다른 시각에 측정한 것이다. 바닥·자세·배터리 상태가 달라지면 차이가 수평 유지 때문만은 아닐 수 있다.
- 보정 한계는 다리당 ±`level.maxCompDeg`°다. 바닥 기울기가 이보다 크면 켜도 수평이 되지 않는다.
- 더 높은 샘플링이 필요하면 펌웨어 쪽 버퍼링이나 게이트웨이 로깅이 필요하다. 이것은 별도 계약 변경이므로 `telemetry`·`embedded`와 합의한 뒤에만 한다.

## 안전

- 비교 기능은 **자동으로 수평 유지를 켜거나 끄지 않고, 활성화·보행 명령도 보내지 않는다.** 사용자가 버튼으로 직접 전환한다. (자동 A/B 시험은 실물 동작이므로 사용자 요청과 승인이 있을 때만 별도 기능으로 만든다.)
- 하트비트·정지 경로에 영향을 주지 않는다.

## 테스트 (`tests/page_harness.js` 확장, 모의 상태만 사용)

- 꺼짐 구간 → 켜짐 구간 모의 데이터를 넣었을 때 모드별 통계와 감소율이 기대값과 같다.
- `enabled=true, active=false` 표본은 켜짐 통계에 들어가지 않는다.
- `walk`가 다른 구간끼리는 비교되지 않는다.
- 축 미설정·센서 무효·표본 부족일 때 숫자 대신 안내가 나오고 `NaN`/`undefined`가 화면에 없다.
- 기존 하트비트·오래된 상태 테스트가 그대로 통과한다.
