# 로봇 텔레메트리, 로깅 및 에너지

인터페이스 변경 전에 기존 펌웨어 패킷 형식과 브라우저 파서를 확인한다. 기기, 게이트웨이, 저장소, UI가 공유할 단일 버전 계약과 단위에 합의하고 [공유 텔레메트리 계약](../robot-dog-orchestrator/references/telemetry-contract.md)을 사용한다.

## 데이터 경로

- 나중에 호스팅 방식을 선택할 수 있도록 기기 전송과 클라우드·공급자별 서비스 사이에 명확한 인터페이스를 둔다.
- 인터넷 연결은 게이트웨이나 브로커를 거치는 인증·암호화된 사용자 및 기기 세션을 사용한다. 현재 ESP32 직접 제어 WebSocket을 인터넷에 공개하지 않는다.
- 모든 동작 요청의 권한을 확인하고 허용 목록 및 만료를 검증하며 재생 공격을 방지한다. 장치에서도 다시 검증한다. 자격 증명을 소스, 브라우저 리소스, 로그, 텔레메트리에 넣지 않는다.
- 재연결, 오프라인 버퍼링, 순서 보장, 중복 처리, 오래된 데이터 표시를 정의한다. 장애를 표시하고 과거 샘플을 최신 데이터인 것처럼 보여주지 않는다.

## 로깅 및 에너지

- 가능한 경우 원본 전압·전류 샘플, UTC 시각, 단조 경과 시간, 시퀀스, 기기 ID, 센서 상태, 보행, 오류를 보존한다.
- 순간 전력은 `V * A`로 계산하고 경과 초를 사용해 Wh로 적산한다. 샘플 공백과 불확실성을 표시하며 데이터를 꾸며내지 않는다.
- INA219 전압·전류만으로 정확한 배터리 잔량을 추정하지 않는다. 배터리 화학 특성·구성과 명시적이고 보정된 산정 방법이 필요하다. 그렇지 않으면 전압과 알 수 없음/추정 상태를 표시한다.
- 사용자가 요청하지 않았다면 보존·내보내기 설정을 불필요하게 확장하지 않고, 공급자별 의존성을 추가하지 않는다.

## 검증

결정적인 테스트 자료로 계약 버전, 단위·스케일링, 잘못된 페이로드, 오래된 데이터, 재연결, 순서가 뒤바뀐 샘플·중복 샘플, 로그 내구성, 게이트웨이 손실을 시험한다. 실제 생산자와 소비자를 대조한다. 로컬 WebSocket 테스트만으로 인터넷 보안이 성공했다고 주장하지 않는다.
