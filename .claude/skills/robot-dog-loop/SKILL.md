# 로봇개 루프 하네스

하네스(오케스트레이터와 전문가 스킬)는 **무엇을 어떻게 만들고 검증할지**를 정한다. 루프 하네스는 그 일을 **작업 목록이 빌 때까지 반복**시킨다. 회차 사이의 기억은 대화가 아니라 파일에 둔다.

## 구성

| 파일 | 역할 |
|---|---|
| `_workspace/loop/BACKLOG.md` | 작업 목록. 항목마다 완료 기준이 있다. 루프가 읽고 갱신한다 |
| `_workspace/loop/LOG.md` | 회차 기록(무엇을 했고, 테스트 결과가 어땠는지). 뒤에 덧붙인다 |
| `_workspace/loop/LOOP_PROMPT.md` | 루프에 넣는 고정 지시와 시작 명령 |
| `.claude/hooks/loop_guard.py` | 루프가 도는 동안 펌웨어 업로드·직렬 포트·로봇 명령을 막는 PreToolUse 훅 |

## 한 회차의 절차

1. `BACKLOG.md`와 `LOG.md`의 마지막 회차를 읽는다. 이전 회차가 중간에 끊겼으면(항목이 `[~]`) 그 항목부터 상태를 확인한다.
2. 위에서부터 첫 `[ ]` 항목 **하나만** 고른다. `[~]`(진행 중)로 바꾼다.
3. `robot-dog-orchestrator` 스킬의 절차와 해당 도메인 스킬·명세를 따라 구현한다. 한 회차에 한 항목만 한다.
4. 검증한다. 웹 페이지를 바꿨으면 `python esp32-robot-dog-code-master/software/robot_control_web/embed_page.py`를 먼저 실행하고, 저장소 루트에서 `python -m unittest discover tests`를 실행한다. 항목에 적힌 완료 기준도 확인한다.
5. 결과를 기록한다.
   - 완료 기준을 모두 만족하면 `[x]`로 바꾸고 `LOG.md`에 한 단락을 덧붙인다(바꾼 파일, 테스트 수, 남은 위험).
   - 만족하지 못하면 `[~]`로 두고 `LOG.md`에 막힌 이유와 다음에 시도할 것을 적는다. 같은 항목이 세 회차 연속 막히면 `[!]`(차단)로 바꾸고 "사용자 확인 필요"에 옮긴다.
   - 사용자 판단이나 실물 작업이 필요하면 `[!]`로 바꾸고 "사용자 확인 필요"에 **무엇을 왜 물어야 하는지** 적은 뒤 다음 항목으로 넘어간다. 답을 추측해서 진행하지 않는다.
6. 회차를 끝낸다. `[ ]`와 `[~]` 항목이 하나도 없고 테스트가 전부 통과할 때만 `<promise>ROBOT LOOP DONE</promise>`를 출력한다. 남은 항목이 있으면 약속 문구를 출력하지 않는다.

## 루프에서 하지 않는 일 (훅이 강제)

- 펌웨어 업로드(`esptool`, `arduino-cli upload`, `compile --upload`). 컴파일만 하는 것은 된다.
- 직렬 포트(COM14 등) 접근, USB 게이트웨이 실행·재시작.
- 로봇 명령(`api/command`의 ARM, WALK, LEVEL, SET 등)과 ESP32 핫스팟 주소 접근.
- 차단되면 우회하지 않는다. 다른 도구나 다른 표기로 같은 일을 시도하지 않는다. `[!]`로 기록하고 넘어간다.

테스트는 모의 상태(`tests/page_harness.js`, 게이트웨이 테스트의 가짜 직렬 포트)로만 한다.

## 작업 목록 항목 쓰는 법

```
- [ ] L3. 한 줄 제목
  - 범위: 바꿀 파일이나 영역
  - 완료 기준: 테스트로 확인할 수 있는 조건 (예: "tests에 X 검증 추가, 전체 통과")
  - 참고: 명세 파일 경로
```

- 한 항목은 한 회차(대략 파일 몇 개, 테스트 포함)에 끝낼 크기로 쓴다. 크면 나눈다.
- 완료 기준이 "보기 좋게", "실물에서 잘 됨"처럼 테스트로 판정할 수 없으면 루프 항목이 아니다. "사용자 확인 필요"에 둔다.
- 순서가 곧 우선순위다. 의존하는 항목을 위에 둔다.

## 시작과 중단

- 시작: `_workspace/loop/LOOP_PROMPT.md`의 `/ralph-loop ...` 명령을 그대로 입력한다. `--max-iterations`를 반드시 둔다.
- 중단: `/cancel-ralph`. 중단 후에는 훅이 풀려서 사용자 승인으로 실물 작업을 할 수 있다.
- 루프가 끝나면 `LOG.md`와 "사용자 확인 필요"를 사용자에게 요약해 보고한다. 소프트웨어 테스트 통과를 실물 검증으로 표현하지 않는다.

## 되돌리기

이 폴더가 git 저장소이면 회차마다 `loop: <항목 ID> <제목>` 커밋을 만든다(푸시하지 않는다). 저장소가 아니면 되돌릴 수단이 없으므로, 바꾸기 전에 `LOG.md`에 바꿀 파일을 적어 둔다.
