# 로봇개 웹 UI

## 빌드

- `npm install`로 Node.js 패키지를 설치한다.
- `npm run build`로 웹 UI를 빌드한다.
- `npm test`로 텔레메트리 파서와 로컬 로깅 테스트를 실행한다.
- `npm test`에는 서보를 구동하지 않는 모의 장치 ARM/STOP·IMU·감시 시간 경계·이동값 상한·재연결 시나리오가 포함된다.
- 빌드 결과는 펌웨어의 `software/robot_dog_esp32/web/index.html.gz.h`에 내장된다.
- 시안 미리보기는 `src/index.html?demo=1`로 연다. 합성 텔레메트리만 표시하며 WebSocket을 열지 않고 ARM/STOP·조이스틱, 로그 저장과 내보내기를 비활성화한다. 미리보기 데이터는 기존 로컬 로그에 저장되지 않는다.

## 텔레메트리 프로토콜 v2

ESP32는 40바이트 바이너리 응답을 보낸다. 웹 UI는 이전 14바이트 v1 응답도 읽을 수 있다. 정수 필드는 네트워크 바이트 순서(상위 바이트 우선)를 사용한다.

| 오프셋 | 길이 | 의미 |
|---:|---:|---|
| 0 | 1 | 패킷 ID `T` |
| 1 | 1 | 프로토콜 버전 `2` |
| 2 | 2 | 상태 비트: bit 0은 MPU9250 초기화, bit 1은 최신 IMU 샘플 유효, bit 2는 INA219 초기화, bit 3은 최신 전력 샘플 유효, bit 4는 보행 ARM 상태 |
| 4 | 6 | MPU9250 X/Y/Z 각도(각 0.01도, 부호 있는 정수) |
| 10 | 24 | LF, RF, LH, RH 순서의 알파·베타·감마 명령 각도(각 0.01도) |
| 34 | 2 | 버스 전압(mV) |
| 36 | 2 | 전류(mA, 부호 있는 정수) |
| 38 | 2 | 메인 루프 시간(µs) |

IMU X/Y/Z는 센서 라이브러리가 반환하는 축 각도이며, 로봇 장착 방향에 대한 보정 전에는 roll/pitch/yaw로 해석하지 않는다. IMU 최신성은 서비스 갱신 주기의 4배, INA219 최신성은 전력 갱신 주기의 4배를 기준으로 표시한다. 이 기준은 표시용 신선도 검사이며 보행 안전 차단 임계값이 아니다. 초기화나 샘플 유효성이 물리적 축 보정 완료를 보장하지 않는다. 서보 각도는 서보 명령값이지 측정 피드백이 아니다.

## 연결 및 안전 범위

웹 UI는 텔레메트리 샘플을 브라우저 `localStorage`에 최대 1,000건 저장하고 CSV 내려받기를 제공한다. 에너지(Wh)는 페이지가 받은 유효한 INA219 샘플 간 전력을 단조 시계 기준으로 사다리꼴 적산한 값이며, 2.5초를 넘는 샘플 공백은 건너뛴다. 로그의 표시 시각은 UTC 벽시계 시각이며, 경과시간 계산과 데이터 최신성 판정은 시스템 시계 변경의 영향을 받지 않는다. 브라우저별 로컬 로그이지 서버의 내구성 있는 중앙 저장소는 아니다. 배터리 잔량 추정은 구현하지 않았다.

## 로컬 ARM/STOP 명령

- 새 WebSocket 연결은 항상 비활성화 상태로 시작하며 제어 클라이언트는 하나만 허용한다. 웹 UI에서 ARM을 누르고 확인해야 하며, UI와 펌웨어 모두 MPU9250 샘플이 초기화·유효·최신 상태인지 확인한다. ARM 요청은 `[0x41, sequence:uint8]`이고, 기기는 `ARMED:<sequence>` 또는 `ARM_REJECTED:<sequence>` 텍스트로 응답한다. UI는 일치하는 응답을 받은 뒤에만 이동 패킷을 보낸다.
- 텔레메트리 요청 패킷은 정확히 `[0x54, 0x01]` 두 바이트이며 이동 명령 버퍼와 분리된다.
- 이동 패킷의 여섯 uint16 값은 각각 정규화된 `[-1, 1]` 명령 범위인 `[0, 20000]`만 허용하며, 범위를 벗어나면 기기는 정지·비활성화한다.
- 즉시 정지 패킷은 단일 바이트 `[0x53]`이다. 정지는 항상 ARM보다 우선하며 이동·회전 벡터를 0으로 만들고 비활성화한다. 기존 이동 패킷의 두 번째 바이트가 `0`인 정지 방식도 호환된다.
- 보행 감시 시간은 정상 수락된 이동 패킷만 갱신한다. ARM 후 IMU 샘플이 무효 또는 오래되면 기기 자체 감시가 정지·비활성화한다. 정지 시 진행 중인 다리 스윙은 목표 지점까지 마무리될 수 있지만 새 스윙은 시작하지 않는다. 타임아웃, 잘못된 패킷, 연결 해제, 페이지 숨김은 정지·비활성화를 일으키며 자동 재개되지 않는다. 텔레메트리 v2 상태 비트 4(`0x0010`)는 기기의 ARM 상태를 표시한다.
- 웹 코어는 이동 벡터를 짧은 임계 구역에서 대기 버퍼에 게시하고, 보행 코어가 루프 경계에서 한 번에 적용한다. 명령 감시 시간은 루프 카운터가 아니라 `micros()` 경과시간으로 비교한다. 이는 코어 간 부분 벡터 갱신을 방지하기 위한 소프트웨어 조치이며, 서보 갱신의 물리적 지연을 보증하지 않는다.
- 브라우저의 ARM/STOP/heartbeat/텔레메트리 송신은 공통 WebSocket 경로를 사용한다. 송신 예외, 연결 오류, 연결 종료 또는 닫힌 연결에 대한 송신 시도를 감지하면 브라우저 상태를 비활성화하고 명시적으로 알린다. 연결이 끊긴 동안 STOP 패킷은 전송할 수 없으므로 기기 측 감시 정지에 의존한다. 브라우저는 최대 30초 간격의 지수형 대기로 재연결을 시도하고, 연결이 끊기면 기존 텔레메트리 신선도와 에너지 적산 기준을 폐기한다. 이전 연결에서 늦게 도착한 텔레메트리는 무시한다. 재연결 후에는 명시적으로 다시 ARM하기 전까지 보행을 재개하지 않는다.
- 이 로컬 프로토타입은 인증된 인터넷 게이트웨이가 아니다. IMU 장착 축 보정, 자세 안정화, 보정된 기울기 한계/차단은 구현되지 않았다. ESP32 직접 WebSocket을 공용 인터넷에 노출하지 말고, 실물 시험은 로봇을 고정하고 전원 차단 장치에 즉시 접근할 수 있을 때만 수행한다.

모의 인증 게이트웨이 경계는 [`software/gateway/README.md`](../gateway/README.md)를 참고한다. 이 별도 서비스는 모의 장치만 다루며 ESP32에 연결하거나 인터넷 원격 제어를 제공하지 않는다.

모의 장치 테스트는 명령 계약과 브라우저 동작을 검사하는 소프트웨어 시뮬레이션이다. 실제 ESP32에서 펌웨어의 타이밍, 동시성, 센서 오류, 서보 응답을 검증하는 대체 수단이 아니다.
