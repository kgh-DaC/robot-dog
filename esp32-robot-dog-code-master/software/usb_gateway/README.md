# 로봇개 웹 보행 제어 (USB 게이트웨이 / 핫스팟 Wi-Fi / ESP32 Wi-Fi)

같은 웹 페이지(`software/robot_control_web/index.html`)로 세 가지 경로를 지원한다. 게이트웨이에서 연 페이지는 맨 위 "연결 방법" 카드에서 USB와 핫스팟 중 하나를 고른다.

| 경로 | 접속 방법 | 특징 |
| --- | --- | --- |
| USB 게이트웨이 | PC에서 `python usb_gateway.py --port COM14` 실행 후 `http://127.0.0.1:8787` | 로봇이 USB로 PC에 연결됨. PC 로컬에서만 접속 가능 |
| 핫스팟 Wi-Fi | 로봇과 PC/휴대폰이 같은 휴대폰 핫스팟에 접속. 게이트웨이 페이지에서 "핫스팟 Wi-Fi"를 고르거나, 휴대폰에서 `http://<로봇 IP>` / `http://robotdog.local` | 케이블 없이 제어. PC·휴대폰은 인터넷 연결을 유지한다 |
| ESP32 Wi-Fi | PC/휴대폰을 `RobotDog-XXXX` Wi-Fi에 연결 후 `http://192.168.4.1` | 케이블 없이 제어. 인터넷 없음, 로봇 근처에서만 접속. 핫스팟 접속이 안 될 때의 예비 경로로 항상 켜져 있다 |

필요한 펌웨어: `tools/servoInitPose/servoInitPose.ino` (CAPS에 `LEASE1 WIFI1` 포함 버전, 핫스팟은 `STA1` 포함 버전).

## 안전 규칙 (펌웨어가 강제)

- 부팅·재연결·새로고침 후 자동으로 움직이지 않는다. **움직임 활성화 → 방향 버튼** 순서로만 걷는다. 유일한 예외는 사용자가 직접 켜 둔 "전원 켤 때 자동 전진"이다 (아래 절, 기본값 꺼짐).
- 활성화한 페이지는 250 ms마다 하트비트를 보낸다. **1초 동안 하트비트가 없으면** (창 닫기, 탭 전환, Wi-Fi/USB 끊김, 게이트웨이 종료) 로봇은 스스로 정지하고 비활성화된다.
- **긴급 정지**는 어느 페이지·노트북에서든 항상 받아들여진다. 페이지에서는 Space 또는 Esc 키도 정지다.
- 한 번에 한 곳만 제어한다 (USB 또는 Wi-Fi 중 하나, 그중에서도 활성화한 페이지 하나).
- 원격 제어가 활성화된 동안 노트북의 `SET/POSE/CENTER/PIN/WALK` 명령은 거부된다 (`WALK STOP`은 허용).
- 기존 시리얼 `WALK <방향>` 명령(4way 노트북)도 같은 1초 리스를 쓴다. 펌웨어가 시리얼 제어를 암묵적으로 활성화하고, 노트북은 걷는 동안 0.25초마다 `HB`를 보낸다. 커널이 죽거나 USB가 빠지면 1초 안에 멈춘다.
- 정지(긴급 정지·비활성화·하트비트 끊김)하면 **모든 관절이 중립 자세(90/45/90)로 천천히 돌아간다.** 노트북으로 잡아 둔 자세(`SET/POSE`)도 중립으로 바뀐다. 게이트웨이를 끌 때는 자세가 저장된 뒤 포트를 닫는다.
- ESP32 Wi-Fi API는 `Host` 헤더가 `192.168.4.1`, 지금의 핫스팟 IP, `robotdog.local`(`:80`은 떼고 비교) 중 하나가 아니면 403 `bad_host`로 거부한다 (DNS 리바인딩 방지). 게이트웨이도 `127.0.0.1:<포트>`/`localhost:<포트>`만 받는다.
- 다른 사이트의 페이지는 로봇 API를 부를 수 없다. 교차 출처 요청(CORS)은 게이트웨이 페이지 `http://127.0.0.1:8787`, `http://localhost:8787`에서 온 것만 허용한다.
- 페이지는 0.75초 안에 받은 유효한 상태가 없으면 하트비트를 보내지 않는다. 상태 응답이 멈추면 로봇이 스스로 정지한다.
- ESP32의 웹 서버는 별도 FreeRTOS 태스크에서 돈다. 느린 HTTP 클라이언트가 있어도 리스 검사·시리얼 STOP·서보 이동이 멈추지 않는다.

시험 전: 로봇을 고정하거나 발을 띄우고, 주변을 비우고, 전원 스위치를 손 닿는 곳에 둔다. 소프트웨어 정지에만 의존하지 않는다.

## USB 게이트웨이 사용

1. Arduino 시리얼 모니터와 COM14를 쓰는 노트북 연결을 닫는다 (포트는 한 프로그램만 열 수 있다).
2. 실행:
   ```
   cd esp32-robot-dog-code-master/software/usb_gateway
   python usb_gateway.py --port COM14
   ```
   시작 시 ESP32 Wi-Fi 이름·비밀번호도 출력한다.
3. 브라우저에서 `http://127.0.0.1:8787`을 연다.
4. 종료는 Ctrl+C. 로봇을 정지시키고 자세 저장을 확인한 뒤 포트를 닫는다.

게이트웨이는 로그인 기능이 없으므로 IPv4 루프백(127.x.x.x)에서만 열린다. `--host ::1` 등은 거부한다.

**명령 없이 열기:** 저장소 맨 위의 `robot_web.bat`을 더블클릭하면 게이트웨이를 최소화된 창으로 켜고 페이지를 연다(`--open`). 이미 켜져 있으면 페이지만 연다. USB를 나중에 꽂아도 게이트웨이가 3초마다 다시 연결한다. Wi-Fi(로봇 자체 Wi-Fi·핫스팟)로 쓸 때는 게이트웨이가 필요 없다: 로봇이 페이지를 직접 보내므로 브라우저에서 `http://192.168.4.1` 또는 `http://robotdog.local`만 열면 된다.

**USB 연결 끊기 / 다시 연결:** 페이지 "연결 방법" 카드의 버튼. 끊으면 게이트웨이가 로봇을 정지시키고 자세 저장을 확인한 뒤 직렬 포트를 놓는다. 그 뒤에는 스스로 다시 연결하지 않으므로 업로드·노트북이 포트를 쓰거나 USB를 뽑아도 된다. "USB 다시 연결"을 누르면 포트를 다시 잡는다(자동으로 활성화되지는 않는다). API: `cmd=DISCONNECT`, `cmd=CONNECT`, 끊은 동안 상태 응답은 `error: "usb_released", released: true`.

## 전원 켤 때 자동 전진 (기본값 꺼짐)

- 켜는 곳: USB 게이트웨이 페이지의 "전원 켤 때 자동 전진" 카드, 또는 직렬 `AUTOWALK ON` / `AUTOWALK OFF` (`AUTOWALK`는 상태 출력). 설정은 보드에 저장된다(`Preferences "autoWalk"`). 켠다고 바로 걷지는 않고 **다음 전원 인가부터** 적용된다.
- 동작: 전원 인가(리셋 원인 `POWERON`) 뒤 5초 기다리고, 10초 전진한 뒤 스스로 정지해 중립 자세로 돌아간다 (`auto_walk.ino`의 `AUTOWALK_DELAY_MS`, `AUTOWALK_RUN_MS`). 브라운아웃·감시 타이머·오류로 재부팅된 경우에는 걷지 않는다(재부팅이 반복돼도 계속 걷기 시작하지 않게).
- 이 동안 제어 주체는 `AUTO`다. 조종자가 없으므로 1초 하트비트 정지는 적용되지 않고, 정해진 전진 시간이 한계다. **긴급 정지는 USB·Wi-Fi 어디서든 그대로 듣는다.** 기다리는 5초 동안 정지·활성화·노트북 자세 명령이 오면 예약이 취소된다. 걷는 동안 다른 곳에서는 활성화할 수 없다(먼저 정지).
- 기울기 정지는 IMU가 정상일 때만 동작한다. IMU가 안 잡히는 보드에서는 넘어져도 시간이 끝날 때까지 다리를 움직인다. USB만 꽂아 보드가 켜질 때도 `POWERON`이므로, 서보 전원이 켜져 있으면 걷는다. 로봇 앞을 비우고 전원 스위치를 손 닿는 곳에 둔다.

STOP은 다른 요청이 응답을 기다리는 중이어도 바로 시리얼로 쓰고, 그 뒤 확인 응답을 한 번 더 받는다. 게이트웨이가 ESP32에 다시 연결하는 동안(최대 4초)에는 `usb_connecting` 오류로 바로 응답한다.

## ESP32 Wi-Fi 사용

1. Wi-Fi 비밀번호는 `12345678`로 고정돼 있다 (`web_control.ino`의 `WIFI_FIXED_PASSWORD`; WPA2는 8자 이상 필요).
   빈 문자열로 바꾸면 첫 부팅 때 무작위 비밀번호를 만들어 플래시에 저장하는 방식으로 돌아간다.
   비밀번호를 아는 사람은 누구나 근처에서 제어 페이지를 열 수 있으므로, 쓰지 않을 때는 로봇 전원을 끈다.
2. PC/휴대폰을 `RobotDog-XXXX`에 연결하고 `http://192.168.4.1`을 연다. 동시에 최대 2대.
3. ESP32 웹 서버는 한 번에 한 요청만 처리한다. 다른 기기가 응답 없는 연결을 잡고 있으면 Wi-Fi STOP이 늦게 도착할 수 있다. 이때도 하트비트가 함께 막히므로 로봇은 리스 시간(1초) 안에 스스로 멈춘다. 즉시 정지가 필요하면 USB 경로나 전원 스위치를 쓴다.
4. Wi-Fi 송신 출력은 배터리 부담을 줄이려고 낮춰 두었다 (8.5 dBm). 로봇 근처에서 사용한다.

## 핫스팟 Wi-Fi 사용

로봇(ESP32)이 휴대폰 핫스팟에 접속하면, PC와 휴대폰은 인터넷을 쓰면서 같은 핫스팟 안에서 로봇을 제어할 수 있다. 로봇 자체 Wi-Fi(`RobotDog-XXXX`, 192.168.4.1)는 그대로 켜져 있다.

**핫스팟 준비**
- ESP32는 **2.4 GHz만** 지원한다. 아이폰은 설정 → 개인용 핫스팟에서 **"호환성 최대화"를 켠다**. 안드로이드는 대역을 2.4 GHz로 둔다.
- 핫스팟 이름(SSID)은 1~32바이트(한글 한 글자 = 3바이트), 비밀번호는 영문·숫자·기호 8~63자이거나 비워 둔다(공개망).

**처음 한 번: 핫스팟 정보 저장 (USB로만 가능)**
1. USB 게이트웨이를 실행하고 `http://127.0.0.1:8787`을 연다 (연결 방법: USB 게이트웨이).
2. 아래쪽 "ESP32 Wi-Fi 접속 정보" 카드의 "핫스팟 설정"에 이름과 비밀번호를 넣고 **저장 후 접속**을 누른다. 로봇이 움직이는 중에는 거부된다.
3. "핫스팟 상태"가 `연결됨 · <이름> · <IP>`가 될 때까지 기다린다 (최대 15초. 실패하면 30초마다 다시 시도한다).
   - `핫스팟을 찾지 못함`: 이름 오타나 5 GHz 전용 핫스팟. `연결 실패`: 비밀번호를 확인한다.
4. 비밀번호는 로봇 보드에만 저장된다 (재부팅해도 유지). 상태 응답·페이지·게이트웨이 출력·git에는 나오지 않는다. **설정 지우기**로 지운다.

**제어**
- 게이트웨이 페이지에서: "연결 방법"에서 **핫스팟 Wi-Fi**를 누른다. 주소 칸에는 로봇의 핫스팟 IP가 자동으로 들어간다. 브라우저가 로봇에 직접 접속하므로 PC도 같은 핫스팟에 연결돼 있어야 한다. 이때 게이트웨이는 페이지만 보내 주고, 명령은 USB를 거치지 않는다.
- 휴대폰에서: 같은 핫스팟에 연결된 상태로 `http://<로봇 IP>` 또는 `http://robotdog.local`을 연다. 안드로이드 크롬은 `robotdog.local`을 못 찾을 수 있으니 IP를 쓴다. 로봇 IP는 게이트웨이 출력이나 휴대폰의 핫스팟 접속 기기 목록에서 볼 수 있다.
- 고른 연결 방법과 주소는 브라우저에 저장된다. 움직임이 활성화된 동안에는 연결 방법을 바꿀 수 없다. 바꾸면 기존 경로의 하트비트가 끊겨 로봇이 정지하므로 다시 활성화해야 한다.
- 로봇에서 연 페이지(192.168.4.1이나 핫스팟 IP)에서는 USB 게이트웨이로 바꿀 수 없다. 브라우저가 사설망 페이지에서 PC 루프백으로 가는 요청을 막기 때문이다. USB로 쓰려면 PC에서 `http://127.0.0.1:8787`을 연다.

**알아 둘 점**
- 핫스팟에 접속하면 로봇 자체 Wi-Fi의 채널이 핫스팟 채널로 바뀐다. 그때 로봇 자체 Wi-Fi에 붙어 있던 기기는 잠깐 끊길 수 있다. 활성 상태였다면 하트비트가 끊겨 정지한다.
- 로봇은 움직임이 활성화된 동안 핫스팟 재접속을 시도하지 않는다 (채널 탐색이 제어 연결을 흔들지 않게 하려는 것). 정지하면 다시 시도한다.
- 핫스팟 비밀번호를 아는 사람은 같은 망에서 제어 페이지를 열 수 있다. 제어는 활성화한 페이지 하나만 할 수 있고 긴급 정지는 누구나 보낼 수 있다 (로봇 자체 Wi-Fi와 같은 모델).
- 게이트웨이 페이지에서 핫스팟 모드로 탭을 닫을 때 보내는 정지 요청은 브라우저가 막을 수 있다 (교차 출처 + keepalive). 이 경우에도 하트비트가 끊겨 1초 안에 정지한다.

## 기울기 센서와 수평 유지

**준비 (한 번만):** `robot_dog_imu_check.ipynb`로 센서를 확인하고, 영점(`IMUZERO`)과 축 방향(`IMUMAP`)을 저장한다. 축 방향이 저장되지 않으면 수평 유지를 켤 수 없고, 페이지에는 roll/pitch 대신 센서 X/Y축 값이 표시된다.

**페이지의 "수평 상태" 카드**
- 좌우 기울기(roll, + = 오른쪽이 낮음), 앞뒤 기울기(pitch, + = 앞쪽이 낮음) 수치와 최근 30초 그래프 (점선은 정지 한계). 그래프에 마우스를 올리면 그 시점의 값이 나온다.
- 좌우·앞뒤 보정량과 다리별 GAMMA 보정 각도
- 센서 상태, 축 설정 상태, 수평 유지 상태 표시와 켜기/끄기 버튼

**동작 방식:** 움직임을 활성화한 뒤 수평 유지를 켜면, 서 있거나 걷는 동안 낮은 쪽 다리는 늘리고 높은 쪽 다리는 줄인다. 보정은 천천히 쌓이며(기울기 1°당 초당 0.6°, 1° 이하는 무시), 다리당 최대 ±6°까지만 한다.

**안전 규칙 (펌웨어가 강제)**
- 수평 유지는 부팅·정지·비활성화 후 항상 꺼진다. **활성화한 페이지(또는 시리얼 제어)만** 켤 수 있고, 축 설정과 유효한 센서 값이 필요하다. 활성화 전에 미리 켜 둘 수 없다.
- 활성화 상태에서 기울기가 **20°**를 넘으면 정지한다 (`tilt_limit`). 수평 유지를 끈 상태에서도 적용되며, 축 설정 전에는 센서 X/Y축 각도로 판단한다. 이미 20° 넘게 기운 상태에서는 활성화를 거부한다.
- 수평 유지 중 센서 값이 **1초** 넘게 끊기면 정지한다 (`imu_lost`).
- 보정이 한계(±6°)에 닿았는데 기울기가 시작 때보다 2° 이상 나빠진 상태가 1초 계속되면 정지한다 (`level_diverge`, 축 방향이나 GAMMA 부호가 틀린 경우).
- 정지하면 보정이 0으로 돌아가고 모든 관절이 중립으로 돌아간다.
- 수평 유지를 끈 상태에서 센서 값이 무효(심한 흔들림·충격)인 동안에는 기울기 검사가 쉬므로, 그 사이에는 기울기로 정지하지 않는다.
- 활성화된 동안에는 제어 중인 페이지만 수평 유지를 켜고 끌 수 있다.

**실측한 보정 방향 (2026-11-11):** 바닥에 서 있는 상태(손 대지 않음)에서 왼쪽 두 다리의 GAMMA를 90°/84°/90°/96°/90°로 바꾸자 roll이 −6.1°/−9.0°/−6.5°/−3.9°/−5.5°가 되었다. GAMMA 각도를 **늘리면** 그쪽 몸을 높이 받친다 (`LEVEL_GAMMA_EXTEND_SIGN = +1`). GAMMA 1°에 roll 약 0.45°이므로, 최대 보정 6°로는 기울기를 약 2.7°까지만 바로잡을 수 있다. 들어 올린 상태에서 눈으로 본 "다리 길이"는 반대로 보이므로 판단 기준으로 쓰지 않는다.

**한계:** 가속도만으로 기울기를 계산하므로 걷는 중의 흔들림이 섞인다. 그래서 보정을 일부러 느리게 했다. 빠른 흔들림까지 잡으려면 자이로 결합(상보 필터)이 필요하다.

## 서 있는 자세 수평 보정 (로봇별 초기값)

중립 자세(90/45/90)로 서 있을 때 몸이 수평이 되도록, 다리별 GAMMA에 더하는 보정값을 찾아 로봇에 저장한다. 저장한 값은 부팅할 때마다 첫 서보 신호 전에 읽혀 **이 로봇의 초기 자세**에 들어간다. 화면과 `STATUS`의 각도는 계속 90 기준으로 나오고, 실제 서보에는 보정값이 더해진다.

```
# 게이트웨이와 노트북을 먼저 닫는다 (포트는 한 프로그램만 쓴다)
python esp32-robot-dog-code-master/software/usb_gateway/level_calibrate.py --check   # 기울기만 측정, 움직이지 않음
python esp32-robot-dog-code-master/software/usb_gateway/level_calibrate.py           # 측정 → 최소 조정 → 저장
```

- **준비:** 평평한 바닥에 네 발로 세우고, 서보 전원을 켜고, 손을 뗀다. IMU 영점과 축 방향이 저장되어 있어야 한다. 수평의 기준은 IMU 영점이므로, 영점은 몸이 실제로 수평일 때 잡은 것이어야 한다.
- **조정 방식:** roll·pitch가 허용 범위(기본 ±1°, `--tolerance`) 안이면 아무것도 바꾸지 않는다. 벗어난 축만, 네 다리 변화량의 제곱합이 가장 작은 조합(좌우 차 + 앞뒤 차)으로 한 번에 최대 3°씩 바꾸고 다시 잰다. 몸 높이와 대각 비틀림은 건드리지 않는다.
- **한계:** 한 번 실행에 다리당 최대 ±8°, 보정값 전체는 ±15°. 최대 8단계.
- **중단 조건:** 기울기가 더 커짐, 로봇이 움직임, IMU 값 무효, 응답 없음, Ctrl+C. 이때는 처음 보정값으로 되돌리고 저장하지 않는다.
- `--no-save`를 주면 조정만 하고 저장하지 않는다 (다시 켜면 이전 값).

**직렬 명령 (USB 전용, Wi-Fi로는 바꿀 수 없음)**
- `TRIM` → `TRIM cur=LF/RF/LH/RH saved=LF/RF/LH/RH source=FLASH|DEFAULT max=15.0`
- `TRIM SET lf rf lh rh` → 지금 적용 (저장 안 함). 활성화·보행·초기 자세 이동 중에는 거부한다. 다리는 천천히 움직인다.
- `TRIM SAVE` → 지금 값을 로봇에 저장.
- 저장된 값이 없으면 펌웨어 기본값 9/1/−1/−9를 쓴다. 이전 값으로 되돌리려면 `TRIM SET <이전 값>` 뒤 `TRIM SAVE`.

발과 바닥의 마찰 때문에 같은 보정값에서도 기울기가 약 2° 달라질 수 있다. 결과가 들쭉날쭉하면 로봇을 살짝 들었다 놓고 `--check`로 다시 확인한다.

## 수평 유지 켜짐/꺼짐 비교

"수평 상태" 카드 아래쪽에 있다. 수평 유지를 끈 구간과 켠 구간의 기울기를 나란히 놓고, 수평 유지가 기울기를 얼마나 줄였는지 숫자로 보여 준다. 이 기능은 기록만 하고 로봇에 명령을 보내지 않는다.

**사용법**
1. 움직임을 활성화한다. 활성화하지 않으면 기록하지 않는다.
2. 수평 유지를 **끈** 상태로 5초 이상 둔다 (서 있기 또는 한 방향 보행).
3. 같은 동작을 유지한 채 수평 유지를 **켜고** 5초 이상 둔다. 순서는 반대여도 된다.
4. 그래프 2개(좌우·앞뒤, 점선 = 꺼짐, 실선 = 켜짐)와 요약 문장, 통계 표를 본다. 그래프에 마우스를 올리면 그 시점의 값이 나온다.
5. "CSV 내려받기"로 표본을 저장할 수 있다 (`used_in_stats`가 0인 줄은 통계에서 뺀 표본). "비교 기록 지우기"로 처음부터 다시 잰다.

**표의 항목:** 표본 수, 구간 길이, 평균(부호 있음), 평균 절대값, RMS(수평에서 벗어난 정도), 최대 절대값, 흔들림 폭(최대−최소). 요약 문장은 RMS가 꺼짐 → 켜짐에서 몇 % 줄었는지(또는 늘었는지)를 말한다.

**기록 규칙**
- "켜짐"은 수평 유지가 실제로 동작 중일 때만이다. 켜 두었지만 아직 동작하지 않는 동안은 어느 쪽에도 넣지 않는다.
- 같은 동작끼리만 비교한다 (서 있기끼리, 같은 방향 보행끼리). 서 있을 때의 꺼짐과 걸을 때의 켜짐은 짝이 되지 않는다.
- 켜거나 끈 직후 1초는 통계에서 뺀다. 한 구간은 최근 60초까지만 남긴다.
- 구간마다 통계에 쓸 표본이 20개(약 5초) 이상 있어야 한다. 모자라면 숫자 대신 어느 구간이 더 필요한지 알려 준다.
- 축 설정이 안 됐거나 센서 값이 무효이면 기록하지 않는다.

**표현 한계**
- 상태를 초당 약 4번(4 Hz) 받으므로 0.25초보다 빠른 흔들림은 보이지 않는다.
- 두 구간은 서로 다른 시각에 잰 것이다. 그 사이에 바닥이나 자세가 달라지면 차이가 수평 유지 때문만은 아닐 수 있다.
- 기록은 페이지 안에만 있고 새로고침하면 사라진다. 남기려면 CSV로 내려받는다.

## 관절 모형

"관절 모형" 카드는 상태 응답의 관절 각도 12개로 네 다리의 모양을 계산해 그린다.

**사용법**
- 보기 전환: **3D**(끌어서 돌리기), **옆**(BETA·GAMMA가 그대로 보임), **앞**(ALPHA가 그대로 보임), **위**.
- **보정 포함**: 켜면 수평 유지 보정과 서 있는 자세 보정(다리별 GAMMA)을 더한 각도, 곧 서보에 실제로 보내는 각도로 그린다. 끄면 기본 각도만 그린다. 표의 GAMMA 칸에는 `기본값 → 보정 포함값`으로 나온다.
- **중립 자세 겹쳐 보기**: 중립(90/45/90) 자세를 흐리게 함께 그려 지금 자세와 견준다.
- 표: 다리별 ALPHA/BETA/GAMMA와 무릎·발 좌표(mm). 좌표는 몸통 중심 기준이다 (x 오른쪽, y 앞, z 위).
- 카드 아래 안내 줄에 서 있는 자세 보정값이 나온다. 이 값을 보내지 않는 옛 펌웨어에서는 "알 수 없음"으로 나오고 모형에 넣지 않는다.

**표현 한계**
- **명령 각도 기준**이다. 서보에 위치 피드백이 없어서 실제 자세와 다를 수 있다 (하중으로 처지거나 서보가 따라가지 못해도 모형은 모른다).
- 상태를 초당 약 4번(4 Hz) 받으므로 보행 중의 빠른 다리 움직임은 띄엄띄엄 보인다.
- **바닥 접촉을 나타내지 않는다.** 몸통은 고정이고 다리 모양만 그린다. 발이 바닥에 닿았는지, 몸이 기울었는지는 이 모형으로 알 수 없다 (기울기는 "수평 상태" 카드에서 본다).
- 치수는 윗다리 51.9 mm, 아랫다리 50 mm, 좌우 어깨 간격 80 mm이다. 앞뒤 어깨 간격 141 mm는 실측하지 않은 원본 값이다.
- 연결이 끊기거나 상태가 오래되면 값 대신 `-`로 표시한다.

## API (두 경로 공통)

- `GET /api/status?session=<id>` → 응답에 `error`가 있으면 로봇 상태를 알 수 없다는 뜻이다 (`connected`는 USB 포트가 열려 있는지만 나타냄). 그렇지 않으면 `link`(`usb`/`wifi`), `connected`, `armed`, `controller`(`NONE`/`SERIAL`/`WIFI`), `youControl`, `walk`, `homing`, `settled`, `resetReason`, `lastStop`, `uptimeMs`, `leaseTimeoutMs`, `angles{LF,RF,LH,RH:[α,β,γ]}`, `wifi`,
  `imu{ready, chip, whoAmI, address, valid, ageMs, accG{x,y,z}, axisDeg{x,y}, zeroed, rollMap, pitchMap, rollDeg, pitchDeg}`
  (모르는 값은 `null`; `rollDeg`/`pitchDeg`는 축 설정 후에만 값이 있음),
  `level{enabled, active, sensorUsable, rollCompDeg, pitchCompDeg, gammaOffsetDeg{LF,RF,LH,RH}, maxCompDeg, tiltLimitDeg}`,
  `standTrimDeg{LF,RF,LH,RH}` (서 있는 자세 보정, 도. 옛 펌웨어에서는 필드가 없음)
- `wifi`: USB 경로는 `{ssid, password, sta}`, Wi-Fi 경로는 `{ssid, clients, sta}`. `sta{status, ip, ssid, host}`는 핫스팟 상태다
  (`status` = `OFF|CONNECTING|CONNECTED|NOT_FOUND|FAILED`, 연결 전 `ip`는 `""`, `host`는 `robotdog.local`). 핫스팟 비밀번호는 어디에도 없다. `STA1` 이전 펌웨어에서는 `sta`가 없다.
- `POST /api/command` (form: `cmd`, `dir`, `on`, `ssid`, `pass`, `session`, 헤더 `X-Robot-Control: 1` 필수)
  - `cmd=ARM | HB | DISARM | STOP | WALK` (`dir=FORWARD|BACKWARD|LEFT|RIGHT|STOP`)
  - `cmd=LEVEL` (`on=1|0`): 수평 유지 켜기/끄기
  - `cmd=WIFI_SET` (`ssid`, `pass`; `pass=`를 비우면 공개망) / `cmd=WIFI_CLEAR`: 핫스팟 저장·삭제. **USB 게이트웨이에서만** 되고, 활성 상태면 `armed`로 거부한다.
    직렬로는 `WIFI_SET <ssid><TAB><password>` / `WIFI_CLEAR`이고 응답은 `OK WIFI_SET` / `OK WIFI_CLEAR` / `ERR <이유>`이다.
  - 오류: `{"ok":false,"error":"not_armed|controlled_by_other|homing_in_progress|walking_active|..."}`
